# D3 L0 重启、旧范围清理与检索对照

2026-11-18。延续 [D3.4 首轮矩阵](D3_FAULT_MATRIX_PLAN.md)。先验证真实固定 Core 的停机、重启和清理，再用固定检索样本判断 L0 是否值得接入。全程使用隔离的 Core、合成数据和临时库；模型与 embedding 均关闭。

1. 写入新旧两个 L0 代次并确认可检索。停止 Core，复用实验适配器验证本地回退与 `transport` 原因。保留同一临时配置和数据目录重启，逐项确认健康、FTS 可用、原始回读与正确 ID 召回。启动窗口和检索恢复窗口都有上限；报告计时不能作为生产 SLA。
2. 清理先完整回读；仅允许删除新代次启用后、同一实验命名空间内更旧代次中已知归属的 L0 ID。对象范围、条数与 session 不符合预期时不发送删除；删除结果不明时不重试。检查旧范围回读和搜索为空且当前范围保持可用，再重启检查旧内容没有回流。此处验证 API 可读性与索引观测结果，未验证磁盘擦除、来源未知的对象、并发迟到写入后的持续清理或 L1–L3。
3. 冻结合成中文来源和期望 ID，覆盖字面锚点、同义改写、跨会话多来源、同词干扰、无证据和已撤销记录。Doggie 使用实际本地查询服务；Core 使用真实 L0 BM25，外部命中必须回绑本地有效来源。用相同查询、候选上限和前五口径，分组报告 Recall@5、Precision@5、误入结果和负查询通过数。两边都是词法能力，这是对语义改写鲁棒性的对照；向量与混合检索增益尚不可判断。质量得分低照实记录，不修改 fixture 以通过门槛。
4. 运行离线单测和完整门禁。普通门禁不得启动真 Core；真实恢复与检索对照显式运行、分别保存报告。仅在隔离、恢复、清理和质量证据均满足拟采用范围时考虑 D4b。

## 运行结果

- [恢复报告](D3_L0_RECOVERY_REPORT.json)：真实 Core 完成全部 5 个步骤；进程停机时回退到唯一有效来源。旧代次清理了 2 条已知 L0，原始查询和搜索均为空；二次重启后仍为空，当前代次仍能召回。复测同一空范围不再发送删除。两次从发起启动到可核对召回的时间约为 3–4 秒，包含进程启动；不能当成稳态请求的 3 秒预算已通过。
- [检索对照报告](D3_L0_RETRIEVAL_REPORT.json)：12 条合成来源、16 个固定查询。Core 独立建 3 个实验范围；Doggie 使用同一固定时钟与本地基线，汇总时按相同查询配对，三轮不当作独立语料。前五精确率为命中数除以实际返回的前五候选数，无候选的正查询计 0；负查询只单列。Core 87 个返回候选均能回绑到当前来源；来源有效不代表能回答问题。

| 对照指标 | Doggie 本地查询 | Core L0 BM25 |
|---|---:|---:|
| 正查询 Recall@5 | 58.33% | 83.33% |
| 正查询 Precision@5 | 19.17% | 64.17% |
| 改写查询 Recall@5 | 0% | 60% |
| 无证据查询正确返回空 | 9/12 | 6/12 |

例如“生产发布批准人的手机号是什么？”没有证据。Core 找到了发布审批记录，但记录不含手机号，因而是误入候选；两边也都在问支付供应商合同号时返回了不能回答问题的支付记录。撤销暗号查询两边均未命中。该对照证明这一固定语料上 Core 的候选覆盖有收益，同时暴露了无证据场景的退化；没有向量、模型回答或真实用户数据参与。

**决定：暂不让 Core 候选进入正式回答。** 下一步先实现并独立评测相关性筛选与弃答，再比较关键词、向量或混合检索的净收益；已知来源逻辑清理的结论不扩展到 L1–L3、多写入者竞争或物理擦除。

npm run d3:l0 -- --retrieval-probe
