# 当前后端架构决策

日期：2026-11-03。适用范围是个人、本地优先的 TypeScript 产品。本文记录当前选择、已知限制与重新评估的触发条件，不宣称远程服务、分布式协调或真实模型验收已经实现。

## ADR-001：继续使用 Hono 与现有分层

**决定：保留 Hono，不在 Q1–Q4 更换框架。**

目标依赖方向是协议适配 → 应用用例 → 领域规则与存储/外部能力，`runtime` 负责组装。R0–R5 与 A1–A3 的已交付边界见[后端验收记录](BACKEND_REPAIR_ACCEPTANCE.md)。当前仍有协议类型/错误依赖与 Store 职责债务；另有 Agent 完成合同缺口和模型重试策略待修，分别见[C0 前计划](PRE_C0_BACKEND_PLAN.md) B1/B2/D2。目录分层不能视为已经完成隔离。Hono 继续承担路由；迁移框架本身不能证明这些问题已解决。

| 选项 | 当前价值与代价 | 结论 |
|---|---|---|
| Hono + 明确用例与契约 | 复用既有路由、安全中间件、Node 生命周期与回归；增加统一 schema/operation 清单即可闭合契约 | 近期采用 |
| 更大型框架（含讨论过的 NestJS） | 可能提供组织、注入和生态约定；需要验证实际收益、迁移量、依赖与 Node 原生 TS 的兼容方式 | 需求出现后独立原型评估 |
| 自建通用框架/插件层 | 当前没有稳定的外部插件需求；会增加维护面和隐含授权风险 | 不预建 |

重新评估的触发条件是多个实现团队需要明确模块治理、重复基础设施已形成可测量维护负担、既有协议无法满足明确需求，或替代方案能用同等安全/生命周期测试证明净收益。框架选择不能放宽审批、MCP allow-list、loopback 或原文审计。

## ADR-002：保留 Node HTTP adapter，并显式维护其成本

**决定：继续使用 [server.ts](../src/http/server.ts) 的 Node adapter。**

当前 adapter 管理原始重复/畸形请求头、GET/HEAD wire body、连接与 body 上限、超时、SSE backpressure、disconnect/cancellation 和 shutdown drain。Hono 的 Fetch Request 层无法恢复已被规范化丢失的全部原始请求信息，因此安全检查仍需要 Node 边界。

代价是自有 adapter 有持续维护负担，不能因功能测试通过就视为标准库之外的安全性已经得到无限保证。后续升级或替换 adapter 时，应比较现有安全与真实 socket 流测试的覆盖和行为，特别是 HEAD/SSE、慢消费者、deadline、半关闭、handler drain 和数据库关闭顺序。只有替代方案能承接这些可执行合同，才安排替换。

## ADR-003：单机 SQLite 与单个队列执行所有者

**决定：当前使用 `node:sqlite` 的 DatabaseSync、事务和同机持久化任务队列，不拆服务或引入分布式队列。**

SQLite 文件是 Bucket、Entry、Memory、pending action 和审计的提交权威。Web/MCP 必须显式指向同一个数据库；这不意味着任意多个 worker 都能并行执行后台任务。当前执行器所有权与 PID/进程故障恢复是单机约束，不能用作跨机器锁、租约或共识。

已知限制包括同步数据库工作占用当前事件循环、写入竞争需受事务处理、任务队列和进程生命周期紧密相关、机器故障期间本地服务不可用。没有测量证据证明当前存在吞吐瓶颈，也没有高可用承诺。不能通过在共享网络文件系统上放一个 SQLite 文件就声称完成分布式部署。

| 触发条件 | 必须先设计的内容 |
|---|---|
| 实测长查询/写入影响交互延迟 | 指标、查询优化、索引、工作线程或单独进程的事务/取消边界 |
| 要求跨机器多实例或故障转移 | 服务端数据库、执行所有权/租约、去重、提交恢复、事件投递与备份方案 |
| 独立部署/隔离 CLI worker | 严格消息契约、授权凭据、最小权限、任务绑定、进程故障与结果落盘语义 |
| 远程手机接入 | 先定义可信设备与撤销、消息防重放、传输信任；不自动要求微服务或多数据库 |

现有取消和防重放不应包装为分布式 exactly-once。未来拆分必须保留正式 Entry/Memory 与双审计在同一事务提交、模型不授予写权限、失败动作可恢复等不变量。

## ADR-004：契约先行，避免投影与文档各自演进

**决定：使用现有 Zod 与统一 operation 清单生成 OpenAPI 3.1，保留 HTTP/MCP 各自协议边界。**

请求、成功响应、错误及 SSE data 具有可执行 schema。HTTP DTO、服务投影、浏览器解析和生成文档必须在同一改动中回归；输出 schema 错误属于服务端 500。自定义 refinement、UTF-8 大小、原文绑定与事务授权继续通过运行时规则和测试保证，OpenAPI 不承担授权职责。

本阶段无需增加 OpenAPI 路由/UI 依赖，也不需要把业务用例迁入框架。完整合同见 [API_CONTRACT.md](API_CONTRACT.md)，产品与远程边界见 [PRODUCT_DECISIONS.md](PRODUCT_DECISIONS.md)、[REMOTE_ACCESS.md](REMOTE_ACCESS.md)。人工浏览器、真实模型/CLI 的验收记录应分别注明运行条件，自动 fake 测试不能替代它们。
