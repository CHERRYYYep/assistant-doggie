# D3 腾讯记忆最小验证执行计划

日期：2026-11-15。状态：**规划完成，实验未启动**。本文把 [任务与记忆接入总设计](TASK_MEMORY_INTEGRATION_DESIGN.md) 的 D3 变成可执行实验步骤。本阶段不改 Doggie 生产路径、不迁移真实数据、不接触 `.env` 或真实数据库，也不因计划获批而自动产生腾讯服务调用。

## 1. 决策目标

D3 只回答一个问题：在 Doggie 继续作为来源、授权、撤销和 TODO 权威的前提下，TencentDB-Agent-Memory 的哪些记忆能力能被安全地用于个人助手？实验结束后必须能作出以下之一的决定：

1. **不采用**：正确性、来源追踪、撤销、隔离或故障回退不满足门槛。
2. **只采用可验证检索**：候选可逐条映射到当前有效 Doggie 来源，其他派生层关闭。
3. **采用检索和 L1**：除检索外，L1 事实提取、跨会话召回及撤销传播也通过。
4. **扩大到 L2/L3**：只有在来源依赖、范围清理、隔离重建都得到实测证明后才可考虑；“搜索效果更好”不足以通过。

D3 不决定、更不实现全面替换本地记忆，也不启动自动任务分发、多人协作、Agent 并行、远程访问或前端改版。

## 2. 分阶段执行

| 子阶段 | 工作 | 产物 | 进入下一步的门槛 |
|---|---|---|---|
| D3.0 固定受测对象 | 选择上游不可变 commit；记录源码地址、许可、Node 版本、锁文件摘要、SDK/API 版本、启动参数和模型配置；核对该 commit 的 scope、清理、索引与 SDK 行为 | `D3_REPORT.md` 的环境清单 | 版本可复现；许可兼容；Node 24 可运行；清理和身份范围有可测接口 |
| D3.1 隔离启动 | 在仓库外临时目录构建 MemoryCore；使用专用临时数据目录、随机本地端口、合成凭据和网络策略；健康检查通过后立即验证隔离 | 启动/停止脚本或人工步骤及脱敏日志 | 确认数据目录、端口、进程与凭据均不指向 Doggie 用户数据 |
| D3.2 最薄调用验证 | 先用 curl/SDK 做能力探测，再建立仅供实验的 TypeScript harness；验证捕获、状态查询、召回、清理、错误和未知响应。若 SDK 发布包与仓库协议不一致，记录并比较直连 HTTP 的代价 | 临时 harness、协议差异表 | 外部响应可严格解析；调用范围固定；超时、超大响应和未知状态可拒绝 |
| D3.3 固定语料与基线 | 生成并版本化 30 条合成 Entry、20 个期望来源查询、8 个任务归属案例；分别跑 Doggie 本地查询和腾讯方案；期望答案在运行前固定 | `fixtures/d3/` 合成数据与基线结果 | 所有 fixture 不含真实个人/项目数据；评分脚本可重放 |
| D3.4 故障与撤销矩阵 | 执行 V01–V12；针对提取前、提取中、召回中、回答前后的撤销注入；测试重启、重复发送、超时未知结果、代次迟到和全范围重建 | 场景逐项结果、日志和复现说明 | 安全/一致性禁止行为为零；不确定结果不会自动重发或被当成成功 |
| D3.5 评估与决策 | 汇总召回、来源准确率、跨主题误入、延迟、索引就绪、模型调用/token/费用；按采用范围门槛形成建议 | D3 报告及采用/拒绝决策 | 不以平均分掩盖安全失败；结论能由原始结果复核 |

每步失败都停止向后推进并记录原因；不得为得到“通过”结论而放松预设语料、来源规则或安全门槛。

## 3. 隔离与数据规则

- Doggie 测试库和 MemoryCore 数据目录都必须是新建临时目录，目录名包含随机实验 ID；实验结束后先生成报告，再清理。清理只能针对本次创建且路径已核验的目录。
- 不读取或复制 `doggie.db`、WAL/SHM、用户导出的备份、`.env`、shell history、浏览器数据或真实 API Key。不得复用默认 `~/.memory-tencentdb/...` 数据目录。
- 实验样本全部人工合成，固定标记 `source=synthetic`。不可使用“脱敏”真实内容替代合成数据。
- MemoryCore 仅绑定 loopback；实验端口随机分配并记录。实验程序拒绝非 loopback endpoint；任何模型/嵌入凭据只经单次显式环境注入，不写入脚本、日志、报告、仓库或请求 dump。
- 真实模型提取属于显式实验调用：启动前单独确认模型、端点、API mode、预算/费用上限和样本范围。未具备这些信息时，先完成无模型协议/故障测试，D3 的质量结论标为未完成，不猜测或读取现存密钥。
- 网络默认仅开放本机 Doggie harness 到本机 Core，以及明确配置的模型端点。Core 不连接用户数据库，不开放公网或局域网监听。

## 4. 固定样本与运行方法

30 条合成 Entry 分三类主题，至少包括：同名实体、前后矛盾更新、低信息语句、同文多来源、可撤销决定、已撤销 Entry、移动 Bucket、待确认输入、不保存输入、模型回答文本和 TODO 用户修改。每条记录有稳定 `synthetic_entry_id`、期望 Bucket、状态、文本、创建顺序和期望可用性。

20 个查询为运行前固定的期望来源集合，覆盖明确事实、跨会话召回、时间更新、Bucket 过滤、同名消歧、撤销后的否定检索、无证据查询、仅 TODO 用户修改和跨主题干扰。8 个归属案例覆盖连续补充、交错目标、明确引用、歧义需澄清和新目标创建。

对每个方案使用相同样本、相同查询顺序、同一模型/提示版本、相同 top-k 与相同调用预算。至少重复 3 次，用于区分确定性错误和模型波动；所有随机参数固定或记录。先跑当前本地 Doggie 基线，再跑腾讯方案。不可在看过结果后修改期望来源；若发现 fixture 定义错误，新增版本并重跑两边，保留旧报告。

运行报告需记录：Doggie commit、上游 commit、Node/OS、锁文件摘要、Core/SDK 版本、索引类型与状态、模型及端点标识（不含密钥）、API mode、prompt version、温度/采样项、开始结束时间、请求数、重试/超时数、响应大小、延迟中位数/p95、token 与费用（端点可提供时）、每条查询的命中来源与引用来源、全部故障注入和清理结果。

## 5. 通过门槛与停止条件

**硬门槛：**V03–V12 不得出现一次越权来源进入模型、撤销来源被作为有效证据、无来源候选被当事实、迟到旧代次重新激活、重复投递产生不可识别重复、服务故障伪装成“无相关记忆”、真实数据/密钥泄漏。任何一例都判相应能力失败，不用召回或速度抵消。

**任务归属：**8 个固定案例全部符合预期。歧义必须澄清；不能按关键词、消息最近顺序或全局最新 WorkItem 静默猜测。

**检索与事实：**20 条查询的 Recall@5 不低于本地基线；被模型引用的事实来源有效率 100%；无来源事实为 0；明确 Bucket 过滤没有越界候选进入模型。若本地满分，则腾讯必须提供可量化的延迟、操作或维护收益，才有继续采用的理由。

**运行质量：**召回满足总设计的 3 秒预算，否则稳定降级；普通保存、确认、撤销和 TODO 操作不等待 Core；Core 停机、超时、索引未就绪和协议错误均走本地路径并有可观察状态。

**L2/L3 单独门槛：**必须证明候选的完整来源依赖和聚合范围可清理/隔离；撤销后全量回归不再返回该来源；清理或重建中崩溃不会把旧 profile 标记可用；旧写迟到不会污染新代次。无法证明时只关闭 L2/L3，不阻止已独立通过的较低层采用。

**立即停止：**隔离目录无法证明、Core 默认落到真实用户目录、身份 scope 含糊、清理 API 可能跨实验范围、来源追踪不可获得、对端超时后无法判定是否已写入且没有安全查重/重建路径、需要未经用户确认使用付费真实模型、发现真实用户数据进入实验。停止后保留脱敏诊断，关闭服务，不做补偿性写入。

## 6. D3 结束时的代码边界

D3 的实验 harness 先放在仓库外临时目录或独立未纳入生产组装的实验目录；除非实验结论需要持久化合同变更，本阶段不改 `src/runtime` 默认装配，不新增生产 schema，不同步现有数据库，不把腾讯 API 加入公开 Doggie OpenAPI/MCP。

若最终需要保存可重复实验资产，只提交合成 fixture、评分代码、脱敏报告和精简适配合同；不提交上游完整源码副本、模型输出原文中的敏感数据、二进制数据库或凭据。是否将薄适配纳入 Doggie 是 D3 结果之后的独立 D4b 决策。

## 7. D3 完成后的交付物

1. 可复现的上游版本与本机启动/关闭说明。
2. 合成数据集、期望来源和查询清单。
3. 本地基线与腾讯方案逐条对照结果。
4. V01–V12 故障/撤销结果及安全门槛判定。
5. 延迟、模型调用和费用数据（能取得时）。
6. 分层采用建议：不采用、检索、检索+L1、或经证明后扩大 L2/L3。
7. 明确仍未知的问题、后续需用户决定的真实模型预算/数据迁移事项。
