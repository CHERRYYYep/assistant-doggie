# D3 腾讯记忆最小验证执行计划

日期：2026-11-18 更新。状态：**L0 恢复、范围清理和检索对照已有结果；完整 D3 尚未验收**。本文把 [任务与记忆接入总设计](TASK_MEMORY_INTEGRATION_DESIGN.md) 的 D3 变成可执行实验步骤。各次实验使用合成数据，不接入生产或迁移真实数据。分阶段证据见 [L0 报告](D3_L0_SMOKE_REPORT.json)、[L1 报告](D3_L1_CORE_REPORT.json) 和 [D3.4 实施计划与结果](D3_FAULT_MATRIX_PLAN.md)。

## 1. 决策目标

D3 只回答一个问题：在 Doggie 继续作为来源、授权、撤销和 TODO 权威的前提下，TencentDB-Agent-Memory 的哪些记忆能力能被安全地用于个人助手？实验结束后必须能作出以下之一的决定：

1. **不采用**：正确性、来源追踪、撤销、隔离或故障回退不满足门槛。
2. **只采用可验证检索**：候选可逐条映射到当前有效 Doggie 来源，其他派生层关闭。
3. **采用检索和 L1**：除检索外，L1 事实提取、跨会话召回及撤销传播也通过。
4. **扩大到 L2/L3**：只有在来源依赖、范围清理、隔离重建都得到实测证明后才可考虑；“搜索效果更好”不足以通过。

D3 不决定、更不实现全面替换本地记忆，也不启动自动任务分发、多人协作、Agent 并行、远程访问或前端改版。

## 3. 隔离与数据规则

- Doggie 测试库和 MemoryCore 数据目录都必须是新建临时目录，目录名包含随机实验 ID；实验结束后先生成报告，再清理。清理只能针对本次创建且路径已核验的目录。
- 不读取或复制 `doggie.db`、WAL/SHM、用户导出的备份、shell history 或浏览器数据。L0 不读取 `.env`；2026-11-15 用户明确授权本轮 L1 实验从现有 `.env` 读取模型配置和凭据（不再要求专用凭据），限 50 次模型 HTTP 请求。凭据仅保留在父进程已有脱敏 transport 内，不进入上游子进程、临时配置、日志或报告。不得复用默认 `~/.memory-tencentdb/...` 数据目录。
- 实验样本全部人工合成，固定标记 `source=synthetic`。不可使用“脱敏”真实内容替代合成数据。
- MemoryCore 仅绑定 loopback；实验端口随机分配并记录。实验程序拒绝非 loopback endpoint；任何模型/嵌入凭据只经单次显式环境注入，不写入脚本、日志、报告、仓库或请求 dump。
- 当前 runner 使用临时 HOME/目录、环境变量白名单和合成凭据，模型及 embedding 明确关闭；这属于进程/配置隔离，**没有实施 OS/container 防火墙来封锁任意外连**。不得将报告表述为已证明操作系统级无网络出口。
- 真实模型提取属于显式实验调用：启动前单独确认模型、端点、API mode、预算/费用上限和样本范围。未具备这些信息时，先完成无模型协议/故障测试，D3 的质量结论标为未完成，不猜测或读取现存密钥。
- 网络默认仅开放本机 Doggie harness 到本机 Core，以及明确配置的模型端点。Core 不连接用户数据库，不开放公网或局域网监听。

## 4. 固定样本与运行方法

30 条合成 Entry 分三类主题，至少包括：同名实体、前后矛盾更新、低信息语句、同文多来源、可撤销决定、已撤销 Entry、移动 Bucket、待确认输入、不保存输入、模型回答文本和 TODO 用户修改。每条记录有稳定 `synthetic_entry_id`、期望 Bucket、状态、文本、创建顺序和期望可用性。

20 个查询为运行前固定的期望来源集合，覆盖明确事实、跨会话召回、时间更新、Bucket 过滤、同名消歧、撤销后的否定检索、无证据查询、仅 TODO 用户修改和跨主题干扰。8 个归属案例覆盖连续补充、交错目标、明确引用、歧义需澄清和新目标创建。

对每个方案使用相同样本、相同查询顺序、同一模型/提示版本、相同 top-k 与相同调用预算。至少重复 3 次，用于区分确定性错误和模型波动；所有随机参数固定或记录。先跑当前本地 Doggie 基线，再跑腾讯方案。不可在看过结果后修改期望来源；若发现 fixture 定义错误，新增版本并重跑两边，保留旧报告。

运行报告需记录：Doggie commit/实验 harness 摘要、上游 commit 与锁文件摘要、Node/OS、Core/SDK 版本、索引类型与状态、模型及端点标识（不含密钥）、API mode、prompt version、温度/采样项、开始结束时间、请求数、重试/超时数、响应大小、延迟中位数/p95、token 与费用（端点可提供时）、逐条原始候选数、经本地来源闸门后的 Entry ID/非准入数、基线对照、全部故障注入和清理结果。目标命中率不得掩盖额外候选：需同时报告 Recall@5、Precision@5 和误入候选。

### 4.1 已完成的 L0 结果及其限制

- 固定上游 commit：`42d4cde50c5a83182fced8c584f9ddb32a620615`；MIT。Node `v24.18.0`、MemoryCore `1.0.2-beta.1`、直接 HTTP（未使用 SDK）、SQLite FTS5/BM25；模型与 embedding 均关闭。每轮包含 30 条中有效的记录及一条额外重复请求记录，查询范围共 31 条。
- 3 轮各 15 个正查询 + 5 个无关负查询。Doggie 词法基线与 Core 经本地来源闸门后的目标 Recall@5 均为 1.0，负查询 15/15 未命中；每个正查询的 top-5 通常有 4 个非期望来源，Precision@5 约为 0.2。两者都未证明高质量语义检索，Recall 相同也没有显示腾讯优于 Doggie。
- 三轮均能按 user scope 聚合跨 session 的 31 条消息、改用另一 user 后为 0 条、删除本轮已知消息 31 条。重复 `x-request-id` 得到不同 message ID：幂等探针失败；未知写入结果必须由外层隔离代次清理，不能盲目重试。
- 每轮把 Core 返回的撤销 Entry 候选交给本地来源闸门，闸门拒绝它；旧 revision 快照也被拒绝。这只验证**实验侧 L0 投影**，不是 Core 原生删除、L1–L3 撤销传播或并发 race 验收。原始候选中未能绑定、被撤销或不匹配的项按 Entry 数量汇总，不把 Core 原始 BM25 结果精确率冒充来源质量。
- 语料尚未覆盖计划中的同文多来源、前后矛盾、Bucket 移动、TODO 用户修改等完整场景；`WORK_ITEM_CASES` 只跑确定性 resolver，不等于多轮用户入口分发链路。V01–V12 未执行，中文语义质量、L1 提取、费用与模型稳定性均未知。
- `npm run d3:l0` 是受支持的实验入口；它要求仓库外固定 commit checkout，拒绝上游 tracked dirty tree，并在退出时停止子进程和删除本次临时数据。直接运行 `live-smoke.ts` 不构成隔离证明。报告记录了没有 OS 网络出口沙箱这一限制。

**判定：L0 smoke 阶段性完成，D3 不通过也未整体完成。**负查询、身份隔离、临时范围清理和本地撤销闸门探针通过；幂等性探针失败；检索质量与语义提升未证明。不得据此启动 Doggie–Core 生产适配或真实数据同步。

### 4.2 本轮真实 L1 核心实验目标与执行边界

用户已授权现有 `.env` 的模型配置和最多 **50 次模型请求**，探针、重试、失败请求均计入。实际配置离线校验为 `gpt-6.1-sol` / Responses；自定义端点只在进程内使用，报告保存端点标识摘要。请求预算由父进程唯一计数器在发送前同步扣减，最多单请求并发，禁止自动重试；达到上限或凭据/端点错误即停止，不为凑满预算继续调用。

先固定 `l1-core-v1` 合成语料：10 个场景、每场景 3 条来源；覆盖中文工作事实、跨主题交错、同名对象、前后更新、多来源合并、长期偏好、决策边界、待确认/不保存/模型输出排除和撤销来源排除。Tencent L1 以原版 `chat` prompt 运行三轮（最多 30 次）；本地 Doggie 对相同已接纳内容做一轮原生结构化提取基线（最多 10 次）。两种提示词和输出结构不同，报告并列给出内容断言覆盖和各自限制，不宣称严格同格式胜负；固定断言不因模型回答而修改。

固定版本 standalone runner 强制调用 Chat Completions，与当前 Responses 配置不兼容。本轮通过上游公开 `LLMRunner` 注入点，直接调用未修改的 `extractL1Memories`（原版过滤、提示、解析、writer），由父进程现有 Doggie transport 调用 Responses。子进程独立临时 HOME/数据目录，关闭 embedding、冲突去重和 L2/L3，不启动调度器；因此不会产生背景模型调用。先验证来源字段、无未知来源引用、输出落盘和隔离，再以固定合成断言评价内容。来源闸门只证明 ID 绑定和当前有效性，不等于自动证明每条事实都被引用原文蕴含。

**本轮明确不覆盖：**Core HTTP 原生 Responses 兼容、线上同步、索引/跨 session 查询、去重合并、L1–L3 原生撤销级联和 V01–V12 完整矩阵。临时目录、凭据零落盘和请求上限先由 fake 测试验证，再运行一次真实批次；记录全部请求次数/token、失败、prompt/source/harness 摘要和时间，不报告无法确定的费用。实验失败也保存脱敏结果并清理进程与临时目录。

#### 4.2.1 本轮结果（2026-11-15）

真实运行结果保存在 [D3 L1 Core 报告](D3_L1_CORE_REPORT.json)。共发出 40/50 次授权上限内的模型 HTTP 请求：Tencent L1 10 个场景各 3 轮（30 次），Doggie 本地提取基线每场景 1 轮（10 次）；没有自动重试。端点返回完整 token 用量：输入 88,698、输出 15,506。报告未记录费用，因为端点未提供可核验的费用字段。`.env` 内容 hash 前后相同，实验子进程正常退出，临时数据目录已删除。

Tencent 运行通过 69/72 次固定文字断言，Doggie 基线为 24/24；Tencent 的 40/40 条落盘记录通过机械来源 ID/scope 校验，SQLite 与 JSONL 记录一致，重开后 L1 保留，删除 L0 后 L1 仍保留。来源校验只证明引用 ID 属于本轮已接纳来源且 scope 相符；文字断言只测固定关键词覆盖，不证明内容由来源蕴含，也不等于来源语义准确率。复查原始报告：同文多来源场景三轮均保留两个预期来源 ID；其中两轮把缓存边界写进同一条记忆并附第三个来源，说明记录粒度有差异。三个漏判均来自发布审批边界用“获批”而非规则要求的“批准”；人工复核三轮都表达了“对外发布尚未获批”。保留原字面分数，不把它当成语义遗漏。

这不是统计有效的胜负比较：两边提示词和输出结构不同，Tencent 跑三轮、Doggie 只跑一轮；Doggie 的 24/24 与 Tencent 的 69/72 不能直接解读为总体质量排名。该结果说明后续需要更好的语义断言与事实级来源验证，目前不足以支持生产采用。报告中的来源/内容结果是诊断性指标；完整检索、撤销传播、去重和 V01–V12 仍待后续阶段验证。

### 4.3 L0 恢复与固定自然语言查询对照

[恢复与检索报告说明](D3_L0_RECOVERY_PLAN.md)记录了真实 Core 停机回退、两次停进程后重启、索引回读、旧范围内已知 L0 ID 删后不再可读的证据。合成自然语言查询上，Core BM25 找回更多目标，但负查询更容易召回主题相近、实际不能回答问题的记录。流程和范围探针通过，质量证据暂不足以开启正式答案的 Core 召回；仍未验证向量/混合检索、整链 V01–V12 或 L1–L3 撤销。

## 5. 通过门槛与停止条件

**硬门槛：**V03–V12 不得出现一次越权来源进入模型、撤销来源被作为有效证据、无来源候选被当事实、迟到旧代次重新激活、重复投递产生不可识别重复、服务故障伪装成“无相关记忆”、真实数据/密钥泄漏。任何一例都判相应能力失败，不用召回或速度抵消。

**任务归属：**8 个固定案例全部符合预期。歧义必须澄清；不能按关键词、消息最近顺序或全局最新 WorkItem 静默猜测。

**检索与事实：**20 条查询的 Recall@5 不低于本地基线；被模型引用的事实来源有效率 100%；无来源事实为 0；明确 Bucket 过滤没有越界候选进入模型。若本地满分，则腾讯必须提供可量化的延迟、操作或维护收益，才有继续采用的理由。

**运行质量：**召回满足总设计的 3 秒预算，否则稳定降级；普通保存、确认、撤销和 TODO 操作不等待 Core；Core 停机、超时、索引未就绪和协议错误均走本地路径并有可观察状态。

**L2/L3 单独门槛：**必须证明候选的完整来源依赖和聚合范围可清理/隔离；撤销后全量回归不再返回该来源；清理或重建中崩溃不会把旧 profile 标记可用；旧写迟到不会污染新代次。无法证明时只关闭 L2/L3，不阻止已独立通过的较低层采用。

**立即停止：**隔离目录无法证明、Core 默认落到真实用户目录、身份 scope 含糊、清理 API 可能跨实验范围、来源追踪不可获得、对端超时后无法判定是否已写入且没有安全查重/重建路径、需要未经用户确认使用付费真实模型、发现真实用户数据进入实验。停止后保留脱敏诊断，关闭服务，不做补偿性写入。

## 6. D3 结束时的代码边界

D3 的实验 harness 先放在仓库外临时目录或独立未纳入生产组装的实验目录；除非实验结论需要持久化合同变更，本阶段不改 `src/runtime` 默认装配，不新增生产 schema，不同步现有数据库，不把腾讯 API 加入公开 Doggie OpenAPI/MCP。

若最终需要保存可重复实验资产，只提交合成 fixture、评分代码、脱敏报告和精简适配合同；不提交上游完整源码副本、模型输出原文中的敏感数据、二进制数据库或凭据。是否将薄适配纳入 Doggie 是 D3 结果之后的独立 D4b 决策。

## 7. D3 完成后的交付物

1. 可复现的上游版本与本机启动/关闭说明。
2. 合成数据集、期望来源和查询清单。

7. 明确仍未知的问题、后续需用户决定的真实模型预算/数据迁移事项。
