# Entry 撤销合同

实现日期：2026-11-03，schema v6。普通删除是撤销有效记录，不是清除全部原文。

## 行为与接口

`DELETE /api/entries/:entryId` 不接受请求体，沿用本地同源安全检查。成功返回 `ok`、`entry_id`、`bucket_id`、`correction_id`、`revoked_at`、`memory_item_ids`。这些 Memory ID 表示退出有效集合的记录，数据库行仍然保留。重复撤销返回首次结果，不新增审计或重置上下文；未知 ID 返回 404。

事务设置 `entries.revoked_at`，更新归档审计为 `revoked`，重建 Bucket 摘要，去除只有该 Entry 支持的已知标签，并写 correction 和上下文版本。原文、Memory 外键、聊天及 PendingAction 执行审计保持可追溯。任何一步失败全部回滚。

有效读取排除已撤销 Entry 及其 Memory，包括详情、自然语言查询、MCP、证据、TODO、热门计数、摘要重建、移动及重新提取。后续同文事实可以作为新 Entry 保存；提取去重只在同一 Entry 内进行，不把一个 Entry 的 Memory 当作另一条的来源。

前端在归档卡片和详情中提供“撤销记录”与解释性确认。成功后更新列表、历史、详情并清空旧查询；不重复提交并发点击；服务端失败不显示成功。历史卡片动态显示撤销状态并移除操作，旧聊天正文作为历史仍可见。移动后卡片使用当前 Bucket。

## 模型上下文与并发

旧模型回答及工具结果没有完整的逐事实依赖图，因此采用保守失效策略：每次首次撤销或删 Bucket，记录当前聊天 sequence 边界与递增记忆版本。之后模型历史只取边界后的内容，不传审计 details；页面保留完整历史。用户可重新提供需要继续的话题，有效 Entry 仍可检索。

归档分类/提取期间记忆发生变化，拒绝基于旧候选继续写入。对话回答期间发生变化，丢弃晚返回的模型/工具结果，显示“记忆已更新，请重新提问”，更新归档状态和操作。归档已经提交的有效新记录不会被这条提示自动撤销。

CLI session 绑定创建时的记忆版本。旧 session 的恢复、提前创建提案的批准和已排队任务启动都重新检查；版本失效报告 `memory_changed`。运行期间失效时不保存晚输出或远端 session ID，任务和 PendingAction 终结为失败，新 session 可以继续。不会将失败误报为成功，也不自动重试。

## 数据保留与限制

- v5→v6 只添加字段/触发器，不推测、清除或重新归属旧 `entry_id = NULL` Memory。它们的来源未知；未来需独立数据整理合同。
- 来源不明的历史标签不被猜测删除；新移动路径会同步已知标签支持，避免新增残留。
- Bucket 标题是独立的组织元数据，撤销不改名或删桶；模型提示明确标题/标签不能作为事实证据。
- 保留审计和历史不代表它们是当前有效知识。用户显式重新输入同一事实仍可重新保存。
- 撤销不删除外部 CLI 已有磁盘会话，不承诺第三方模型已遗忘历史；Doggie 停止复用相应 session。
- 本阶段未实现跨消息的精细事实依赖图、彻底擦除、远程认证或离线同步。
