# 腾讯记忆接入前的本地任务阶段

日期：2026-11-13。实施目标：完成 [总设计](TASK_MEMORY_INTEGRATION_DESIGN.md) 中可独立于腾讯服务交付的个人助手基础。本轮不安装腾讯依赖、不创建外部适配器/同步队列、不访问真实库或密钥。

## 1. 目标与验收

1. 用户在长期对话工作区创建明确的工作目标（WorkItem），区分 TODO、队列任务和 CLI 执行；目标和验收要求持久化。
2. 用户明确选择目标后创建只读执行提案；原指令、目标版本、执行者、工作区和会话关联不可被替换。批准仍为独立动作。
3. 相同目标可以顺序继续；用户选择“新会话”或明确恢复该目标的既有成功会话。跨目标、跨环境、失败/取消或记忆版本失效的恢复必须拒绝。
4. 提供纯归属规则及 HTTP 解析：明确 ID/唯一完整标题可定位，多个或模糊候选要求选择。初版页面使用任务卡片选择，不由普通聊天猜测并启动 CLI。
5. 目标状态独立于执行状态：执行成功不自动完成；失败/单次取消转阻塞；取消整个目标先记录取消请求并等待执行终态。一个目标最多一个已排队/运行尝试。
6. 同源 HTTP、严格请求/响应契约、OpenAPI、前端校验同时更新；刷新和断线后能恢复观察，不重复批准。
7. 新建目标与创建尝试有请求 ID 去重；同 ID 不同内容冲突。状态修改与目标编辑用 revision 防止覆盖并发变化。持久化事件提供审计。
8. 目标可关联有效 Entry、Bucket、用户消息。详情动态返回来源可用性，不从已撤销来源构建新上下文。任务指令进入聊天时间线但不自动归档，也不混入普通模型聊天历史。

## 2. 实施顺序

| 阶段 | 文件职责 | 完成条件 |
|---|---|---|
| L1 领域与存储 | `domain/work-item.ts`、schema v8、`storage/work-items.ts` | 状态/归属规则、目标/来源/请求去重/事件/执行绑定；v7 升级与重开测试 |
| L2 受控执行关联 | `storage/agents.ts`、`agent/service.ts`、本地任务服务 | 提案、批准、启动和完成均检查目标；取消和重启可协调；既有独立 CLI 行为兼容 |
| L3 HTTP 与页面 | operation/schema/DTO、工作目标卡片与执行表单 | 创建、查看、编辑、继续、批准/拒绝/取消、完成/重新打开链路可用 |
| L4 联合验收与记录 | fake runner/临时库回归，文档状态与提交 | 相关检查及 `npm run check` 通过，记录限制和腾讯接入前终点 |

L1 的目标可编辑；编辑/终态/重新打开增加 scopeRevision，使旧提案与会话不能继续携带旧目标。审批与执行导致的一般状态变更只增加 revision，不使已经批准的尝试自我失效。运行中禁止编辑目标；终结和重开不复用旧批准。旧独立 CLI session 不自动归属到新目标。

## 3. 最小 UI 与范围

沿用现有页面，长期对话内增加可折叠工作目标区：创建表单、目标列表、目标详情、执行提案与历史。用户无需输入内部 session UUID，恢复时从该目标的成功尝试选择；服务端仍重新检查。保留原 Agent 工具区，用于既有独立任务和工作目录登记。

正常聊天发送、归档确认、TODO、MCP 工具与执行权限保持现有合同。初版明确选择目标后分发，不实现自然语言全自动分发、多任务拆分/并行、自动验收、远程接入、自动记忆采集或腾讯同步。一次取消请求失败不显示已取消；状态冲突刷新对象并保留用户草稿。

## 4. 回归要求

- 存储：真实 v7→v8 临时库、旧对象保留、重开、事务失败回滚、请求重放/冲突、陈旧 revision、来源撤销/删桶。
- 领域：交错任务明确引用、同名标题歧义、不使用全局最新任务、终态与取消规则。
- 执行：跨目标 session 拒绝、目标编辑使旧提案失效、同目标排他、明确批准、失败/取消不复用、记忆撤销晚输出拒绝、重启协调。
- HTTP/UI：严格 schema、同源限制、完整业务路径、XSS、失败不伪报成功、刷新恢复与草稿保留。
- 普通测试均 fake model/runner，临时 SQLite，无公网和真实 CLI；实施结束运行完整门禁。真实自用与腾讯效果不作为本轮已完成项。

## 5. 实施状态

2026-11-13 已完成 L1–L4 的本地 MVP：

- 新增 `WorkItem` 领域模型、schema v8、来源可用性、请求去重、事件和目标/执行关联。
- 复用现有只读 Agent 审批边界；跨目标 session、旧范围提案、失败/取消 session 和撤销后的晚结果均拒绝。
- 新增 `/api/work-items` 相关严格契约、OpenAPI 和浏览器调用；前端在长期对话中提供明确目标表单和目标卡片。
- 任务目标消息保留在页面时间线，但被排除在普通模型聊天历史之外；目标状态不等同 TODO 或单次执行结果。
- `npm run check` 通过；新增 9 个后端目标/存储回归，原有后端与前端回归保持通过。

本阶段仍未接入 TencentDB-Agent-Memory、未自动从普通聊天分发、未实现多目标并行、未迁移真实数据。目标 UI 的执行提案目前创建待批准 Agent 任务，批准仍在既有 Agent 工具区完成；后续可把两者合并为更完整的单卡片交互。
