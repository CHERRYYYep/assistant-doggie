# 单会话 Agent Harness

## 1. 目标

Doggie Agent Harness 将本地长期记忆接入普通对话，同时保持严格的工具边界：

1. 读取持久化对话历史和活跃 Bucket 上下文；
2. 需要历史事实时搜索 Entry 级记忆；
3. 在统一归档流程完成后，让模型解释结果并回答问题；
4. 不允许模型通过聊天响应绕过服务端确认或直接执行未注册操作。

对话和记忆共享一个时间线。服务端在调用回答模型前先处理本轮归档；如果结果为 `needs_confirmation`，回答必须明确“尚未保存”，并把用户引导到确认卡片。

## 2. 工具边界

当前对话回答阶段只开放只读工具：

- `list_active_buckets`：读取活跃 Bucket 概览；
- `search_memory`：提交自然语言记忆查询，返回 Entry、Bucket、证据和查询计划；
- `get_bucket_detail`：读取一个 Bucket 的完整详情。

归档和确认写入由 `CanonicalRuntime`/server 统一执行，不属于回答阶段的工具 allow-list。这样可以防止模型重复创建 Entry、把待确认输入说成已保存，或把工具输出中的文本当成系统指令。

## 3. 受控循环

Harness 对每轮模型调用设置硬上限：

- 默认最多 4 个 tool round，调用方最多配置到 8；
- 每轮最多 8 个 tool call；
- 单次参数最多 32 KiB，单次结果最多 64 KiB；
- 记忆上下文和历史消息都有字节/数量上限。

未知工具、非法 JSON、过大的参数、重复调用或工具错误均作为数据返回或固定错误结束，不执行任意 shell、文件、浏览器或数据库命令。

## 4. 对话流程

```text
用户消息
  → 保存 user 消息
  → 统一 archive 流程
  → 读取历史和当前 archive projection
  → 模型直接回答或请求只读工具
  → 校验工具名和参数
  → 执行查询并返回 JSON 数据
  → 保存 assistant 消息
```

模型回答必须使用用户语言，并区分：已保存、等待确认、未保存、查询证据和模型推断。跨多个 Bucket 时要说明结果范围，避免把单条 Entry 推断成整个 Bucket 的结论。
