# Rust Work Memory MVP 规格

## 1. 产品目标

提供一个本地、单用户、单入口的工作记忆 Agent：用户只需输入自然语言，系统负责理解上下文、归档事实并在之后用对话方式检索。

## 2. 归档 action

| action | 行为 |
|---|---|
| `append_existing` | 保存到一个已确认的活跃 Bucket |
| `create_new` | 创建一个新的 Bucket 并保存第一条 Entry |
| `ask_user` | 只保存待确认尝试，不创建 Entry |

自动归档必须同时满足：候选目标有效且唯一、输入含有足够事实、confidence 通过服务端门控。模型 confidence 不是最终持久化授权。

低信息输入包括纯指代、无主体的状态短句和无法区分多个候选的更新。此类输入应返回确认卡片，即使模型给出高分。

## 3. 确认交互

确认响应至少包含：

1. 推荐 Bucket；
2. 备选 Bucket；
3. 模型判断理由；
4. 保存到推荐 Bucket；
5. 保存到其他 Bucket；
6. 创建新的 Bucket；
7. 不保存；
8. 归档后修改 Bucket 的入口。

服务端必须验证 confirmation attempt、原始文本和目标状态。客户端不得通过修改 JSON 直接把 pending 归档变成已确认写入。

## 4. 对话和查询

对话路由先处理归档，再生成回答。回答可以使用只读记忆工具搜索历史，但不能重复写入本轮 Entry。

自然语言查询至少支持：

- Bucket 名称；
- Entry 原文；
- summary、tag、entity；
- 相对/绝对时间范围；
- Bucket 状态；
- 结构化字段；
- 关键词和字段匹配的组合；
- 结果重排、evidence 去重和多 Bucket 聚合。

“查询接口 A 最近两周的压测结果”必须按多个 Entry 处理，而不是默认只查一个 Bucket。

## 5. 非目标

当前 MVP 不提供认证、多租户、团队协作、外部动作执行、文件/图片索引、通用插件系统或公网部署安全能力。
