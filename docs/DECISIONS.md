# 架构决策记录

## ADR-001：MVP 使用 SQLite

状态：接受

原因：

- 新手友好。
- 本地运行简单。
- 不需要部署数据库。
- 足够验证单用户 MVP。

后续条件：

- 多用户。
- 大量数据。
- 需要云同步。

满足以上条件再迁移 PostgreSQL。

## ADR-002：MVP 使用 Streamlit

状态：接受

原因：

- 快速做出输入框和详情页。
- 不需要前端工程复杂度。
- 适合产品验证。

后续条件：

- 需要正式 Web App。
- 需要更复杂交互。
- 需要移动端适配。

满足以上条件再考虑 React/Next.js。

## ADR-003：第一版不引入多 Agent 框架

状态：接受

原因：

- MVP 流程可以用普通函数完成。
- 多 Agent 增加调试难度。
- 产品逻辑还没稳定。

后续条件：

- 出现多个专业 agent。
- 需要复杂状态机。
- 需要人工审批。
- 需要长期运行任务。

## ADR-004：分类和提取使用 Structured Outputs

状态：接受

原因：

- 业务代码需要稳定 JSON。
- 可以减少解析失败和字段缺失。
- Pydantic schema 适合 Python 项目。

## ADR-005：原始输入不可丢失

状态：接受

原因：

- LLM 总结和提取可能出错。
- 用户事后需要查原文。
- 纠错和重算依赖原始输入。
