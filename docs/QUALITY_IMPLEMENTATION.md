## 设计约束

- 撤销是用户明确操作；不由模型自动决定。不新增 MCP 写工具。
- 首先使用现有 Node/SQLite/Zod/Hono；只有可证明必要时才增加依赖。
- 请求校验错误与服务端响应契约错误分别返回 400 与脱敏的 500。
- 浏览器只加载可直接执行的 TypeScript 剥离产物，不将 Node/Zod 服务端依赖引入浏览器。
- 被撤销内容可能存在于旧聊天和旧模型答案中；有效记忆和模型历史必须同时处理，不能只隐藏详情。
- 模型调用期间发生撤销时，不能把撤销前生成的答案作为新的有效上下文保存；需要检查并发失效。
- 各阶段完成后更新本记录与产品状态，运行完整门禁并创建独立提交。用户已授权连续执行上述阶段，不在阶段之间重复等待确认。
