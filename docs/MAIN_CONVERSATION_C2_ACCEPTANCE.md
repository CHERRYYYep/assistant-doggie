# C2 主对话澄清验收

2026-11-19。C2 交付单用户、单机的可恢复澄清预览；旧聊天仍是默认入口。C3 才接续目标材料和受批准的执行，C4 再用对照结果决定是否切换默认入口。

## 操作与边界

1. 在聊天底部勾选「启用主对话预览」。同一浏览器标签页刷新会保留该设置。
2. 有 TCP、UDP 两个计网 WorkItem 时，输入「帮我修改那个计网实验」。等待卡展示原请求、候选与验收提示；可以选择、点「都不是」、补充这条请求或取消。新的普通发言不会消费卡片。
3. 点击「补充这条请求」再发送「抓三次握手那个，只改报告，SYN 和 SYN-ACK 写反了」。回执和卡片保留目标关联与补充。选择后还可继续补充；预览只录入任务要求，不读取工作区、不调用 CLI，也不会自动归档补充。
4. 刷新或重启服务后读回卡片，历史窗口外的待澄清卡也能恢复。目标关闭、范围变化或来源撤销时，旧绑定变为不可消费，卡片提示重新发起。

## 数据与恢复

- [路由和契约](API_CONTRACT.md#主对话预览c2)：`POST /api/conversation/turns` 写入，`GET /api/conversation/clarifications` 恢复。没有隐式批准字段。C2 回执提供消息 ID；原归档/确认和 WorkItem 路由继续独立。
- [v9 迁移](../src/storage/schema.ts) 新增澄清卡及请求回执。原文与所有显式补充保存在聊天行中，补充记录引用同一张卡和原消息；列表只投影最近一次补充。C3 组装上下文时须按关联读取，不用列表上的最新一句代替完整约束。
- 自动绑定只接受显式 ID、按现有规则全库唯一的完整标题，或已关联澄清回复中能同时区分当前候选、且在未截断的活跃目标池唯一的限定短语。词法排序、句中提及、单个弱候选、截断结果均不授权绑定。标题比较与现有 WorkItem 精确匹配一致；完成或取消的目标不自动恢复。C2 用确定性问句，不依赖真实模型猜选择。
- 活跃 WorkItem 候选池最多检查 100 条，卡片最多展示 5 个候选；同时最多 20 张等待卡（含已失效但尚未取消的等待卡），列表优先返回全部等待卡，其余为最近历史，总计最多 40 张，支持按已知 ID 操作，不提供历史分页。候选引用按照当前范围和来源重检，旧引用可保留作审计。
- 卡片写入、消息和回执在同一事务。常规回合先登记请求，再在模型调用之外原子发布回答和回执；归档沿既有独立事务。若进程中断或回答发布失败，未完成请求不会自动重新发送。页面可对响应丢失做原请求核对或重试；刷新后应先看历史，浏览器不跨刷新存储待重试的原文。
- 正式迁移仅用临时库验证。不修改真实数据库；真实升级前应先进行一致性备份并确认恢复流程。关闭预览只恢复原入口，不降级 schema。

## 回归证据

| 固定样本 | 自动化检查 |
|---|---|
| 同 Bucket 下 TCP／UDP、术语插话、关联补充、重开库 | 两个候选均可见；插话正常答复，旧卡版本不变；补充绑定 TCP，后续补充仍指向同一原请求。 |
| 同名、弱候选、无候选、非目标的标题提及、截断 | 坚持未绑定；可拒绝候选；明确完整标题才绑定；自带材料改写走直接回答。 |
| 多卡、真实 loopback 重放、另一页陈旧选择 | 相同请求返回同一回执；改变载荷或旧版本被拒绝；只取消指定卡。 |
| 更新范围、撤销来源、事务故障、旧库升级 | 旧选择和补充不能继续消费；完整回滚；v8 保留原数据，可恢复后重试迁移再重开。 |
| 原归档和确认、分离隐式批准 | 旧确认接口仍可处理原提案；「好」不消费澄清或审批；未知批准字段拒绝；澄清新增 Entry 和 CLI 尝试均为 0。 |
| Web 恢复、草稿关联、重试和转义 | 预览关闭时不访问新路由；补充带卡片 ID 与版本；断线后重用原请求键；409 重读状态；候选和原文按文本显示。 |

定向验证：`node --test src/http/main-conversation.test.ts`、`npm run test:web`。阶段门禁：`npm run check`、`git diff --check`。完整门禁通过（后端及项目测试 569 项、前端 62 项）。这些固定样本只证明合同；真实模型语义效果、长历史证据质量及实际浏览器自用体验尚未评测。
