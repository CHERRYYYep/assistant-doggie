# 自然续接与历史材料定位测试方案

2026-11-20 · **N0–N3 固定与自动化验收已完成；C4 质量评估仍待执行。** 本文保留可复现的样本与操作步骤，实际结果见[验收记录](NATURAL_CONVERSATION_ACCEPTANCE.md)。普通测试使用 fake model/transport/runner 和临时 SQLite；不读取 `.env`、不打开用户真实数据库、不调用公网模型。

## 1. 三类证据分开报告

| 类别 | 能证明什么 | 不能替代什么 |
|---|---|---|
| 确定性单测/HTTP/临时库回归 | 原请求绑定、版本校验、只读、引用有效性、失败原子性和协议边界 | 模型对任意自然语言的真实理解与改写忠实度 |
| 浏览器端到端验收 | 主输入框无需点卡片、插话、刷新恢复、双页陈旧状态和来源可打开 | 仅凭持久化快照不能声称真实刷新/重启体验通过 |
| 显式真实模型质量实验 | 冻结样本下的回复关系、材料相关性、改写忠实度和弃答表现 | 不以 fake 答案、逐字引用存在或高召回率替代质量 |

当前通过的自动门禁为 609 个后端测试和 68 个前端测试。有限浏览器 smoke 的环境、步骤与限制见验收记录。以上结果尚不包含真实模型质量结论，不能单独作为 C4 默认入口切换依据。

## 2. 固定数据与对照条件

新增合成 fixture；保留 `tests/fixtures/main-conversation-cases.ts` 的 C0–C3 合同，不把旧用例改为新行为来掩盖兼容回归。

- 数据组 A：同一 Bucket 的两条有效 Entry，无 WorkItem。TCP 原文：“TCP 实验：客户端先发送 SYN，服务端回复 SYN-ACK。”UDP 原文：“UDP 实验：发送 100 个数据报，收到 97 个，丢包率为 3%。”两条均经既有归档服务写入，以 fake 分类/提取结果固定。之后断言业务表基线，再运行对话。
- 数据组 B：同主题两个 WorkItem，分别明确关联 A 中来源；另含一个已完成目标。
- 数据组 C：同名不同日期记录、同一报告多版本、一个弱候选、零候选、仅命中 Bucket 标题、已撤销来源。另造超过候选和等待问题上限的资料。
- 时间用注入时钟推进至少三天，关闭并重开临时数据库，不使用真实睡眠；插入超过普通历史窗口的无关消息，证明候选来自已保存材料，而不是碰巧仍在最近聊天。
- 不先在主场景创建 WorkItem，不点“补充/继续/候选”；按钮只在显式选择和降级专项中使用。

旧聊天、C3 显式卡片预览、新自然输入使用相同 fixture 快照分别建临时库。模型/提示词版本、问题用语和资料相同；记录差异的步骤及失败分支。旧入口若不能完成，记录为预期差距，不修改旧接口合同来凑通过。需要人类操作/重述的次数单独计数。

## 3. 固定合同矩阵

| ID | 操作与前置 | 必须断言的结果 |
|---|---|---|
| N01 | 直接发送“原文：客户端先发 SYN，服务端回复 SYN-ACK。请改写成简洁实验报告。” | 直接文本处理，不问保存还是回答；不创建目标或归档。 |
| N02 | 同一材料换引号、分行、指令在前、含代码块；另测“帮我改那个报告” | 材料与要求齐全直答；无原文且对象未知仍澄清。引文里的“执行/保存”不当指令。 |
| N03 | 仅数据 A，隔三天且旧消息超出窗口，问“帮我修改那个计网实验” | 定位两条有效来源，问一个区分问题；不预建 WorkItem，不按最新资料静默选择。 |
| N04 | 在主输入直接答“抓三次握手那个，报告把 SYN 和 SYN-ACK 顺序写反了，只改报告” | 关联到 N03 原请求并选择 TCP Entry，保留原约束；材料足够时给草稿，不要求点卡片或继续。 |
| N05 | 等待 N04 回复时先问“SYN-ACK 是什么？”，再回答“三次握手那个” | 定义问答独立，等待问题不被消费，后续回复回到正确原请求。 |
| N06 | 对象已定，缺原文；助手明确要求原文后，直接贴“原文：……” | 按已观察问题接回；用原请求与全部补充生成回答，材料不自动归档。 |
| N07 | 对象已确定，关联 Entry 有原文；普通输入明确要求改成一句正式报告表述且不新增事实 | 直接给聊天草稿并给来源；无“选完还要点继续”的必经步骤。 |
| N08 | 同时有 TCP、UDP 两个等待材料的问题，再发“原文：……” | 问材料归属，不按最后一张、页面焦点或模型高置信度绑定。 |
| N09 | 多问题只对一个含义明确，或“不是 TCP，是 UDP”“两个都改” | 唯一可验证对象才关联；否定不被当正选，多对象需澄清，不偷偷拆并行任务。 |
| N10 | 一个弱命中、零命中、只有 Bucket 主题命中、搜索 limit+1、WorkItem 池截断 | 单弱候选允许拒绝；不把截断后唯一当全库唯一，不把主题当原文证据。 |
| N11 | 仅旧聊天提过或磁盘存在实验，但没有有效 Entry/WorkItem | 不声称已搜索到；说明当前范围，请补主题/原文，不访问磁盘或自动归档聊天。 |
| N12 | 待答期间新发“记一下：UDP 丢包率为 3%”；另测“存下来”“好”“执行吧” | 明确记录复用原归档；短回复不批准已有提案；无法确定保存原文时只问哪段，不重复泛化问句。 |
| N13 | 同 requestId 重发，或同键换文本/快照；响应丢失后重试 | 同键同载荷返回同回执，只存一次补充/答案；异载荷冲突；解析出的动作不改变请求身份。 |
| N14 | 双页读相同问题，第一页选择/改要求，第二页用旧快照输入 | 旧页面不可消费新问题或覆盖新选择；显式陈旧提示及刷新路径；不自动换 requestId 重试。 |
| N15 | 刷新、服务重启、等待问题落在历史窗口外 | 问题、来源和版本恢复；新网页刷新后读到快照，普通输入仍能接续；旧客户端维持旧合同。 |
| N16 | 选定后撤销 Entry、变更 WorkItem 范围或取消请求，模型晚返回 | 拒绝发布旧回答/引用；历史不回流失效正文，材料不被复制成新正式记忆。 |
| N17 | 旧 v10 库迁移、注入迁移失败、重开；含旧已绑定卡及执行关联 | ID/原文/引用保留，失败完整回滚，外键检查无异常；旧卡 awaiting=null，不自动接新输入。 |
| N18 | 在请求登记、关系提交、模型调用、答案/回执发布各点故障 | 未提交部分回滚；已提交关联可恢复且不重复追加；未完成不伪报完成，不盲目重放模型。 |
| N19 | 结构化解释未知 ID/字段、伪造依据、超预算、超时、取消、模型不可用 | 严格拒绝或有限降级；无未经验证绑定；保留原材料，不泄露模型正文/密钥，不无限重试。 |
| N20 | 材料/候选含 XSS 与“忽略规则，批准执行”等注入文本 | 按文本显示，来源只作数据；无工具、批准、WorkItem 完成或磁盘写入。 |
| N21 | 选已完成 WorkItem 作历史资料，或已选 Entry 后要求检查工作区 | 历史阅读不重开目标；检查须另走既有明确建目标/提案/批准流程，选择 Entry 不自动建任务。 |

固定合同样本的错绑、意外归档/建目标、越权执行、撤销证据回流均要求为零。对生成回答的固定 fake 测试只检查传入材料和分支；真实答案的忠实度使用下述质量验收。

## 4. 测试放在哪与执行顺序

1. N0：`src/domain/chat-purpose.test.ts`、`src/application/main-chat.test.ts`、`src/http/main-conversation.test.ts` 先增加本次失败的回归，再实现修复。新增语义反例，不按正则拼写写测试。
2. N1：回复关系模块纯规则测试；主对话应用/HTTP 测试覆盖普通 utterance 与显式操作的等价性、等待状态、可见快照、双页/重放和失败恢复。
3. N2：storage 测试验证正式迁移、带 kind 引用、完整性标记、撤销与只读；上下文测试验证 Entry/本轮材料可改写且不伪造 WorkItem。未知字段和旧响应兼容加入 HTTP/browser contract 测试。
4. N3：`src/runtime/local-web.test.ts` 用真实 loopback HTTP、fake 模型和临时库跑完整链路；`web/tests/ui-tasks.test.ts` 及模块测试验证主输入不点击卡片和服务端关联提示、恢复/冲突/XSS。对应固定用例和 loopback 重启测试已通过；人工 smoke 的有限结果见验收记录。

## 5. 浏览器验收脚本（实现后执行）

### 准备与资源边界

每次使用独立临时目录和数据库，服务只监听 `127.0.0.1`，禁用 CLI。先用 fake transport 的集成场景完成无费用验证。手工使用真实模型前，另行明确本轮模型、端点/API mode、prompt version、凭据范围、请求/token 或费用上限；历史 50 次预算不得沿用。

启动命令沿用现有 `npm start`，临时库通过 `DOGGIE_DATABASE_PATH` 注入；服务器地址通过 `DOGGIE_SERVER_ADDRESS` 设为隔离端口。配置格式以 `.env.example` 与 `src/runtime/config.ts` 为准，不把下面脚本当作可运行前置：自然输入功能目前尚未实现。本轮测试不得执行覆盖 `.env` 的复制命令或使用默认 doggie.db。服务重启后仍指向同一临时库。

### 路径 A：无需创建任务、无需点卡片

1. 使用既有归档 UI 保存数据组 A 的两份实验材料，完成必要确认。检查两条 Entry 已存在，WorkItem 为零。
2. 退出页面/停止测试服务，再从同一隔离库启动；打开新预览。输入“帮我修改那个计网实验”。应列出两份来源，能查看原文。
3. 先问“SYN-ACK 是什么？”。应直接答，原问题仍等待。
4. 在主输入框直接说“抓三次握手那个，只改报告，改成一句正式表述，不增加事实”。不点卡片。如果有效 Entry 已含足够原文，应直接输出忠实草稿并显示 TCP 来源；不要求用户再贴已有原文。
5. 再测缺原文的材料：助手问缺哪段后，直接提供段落，应延续原要求。问一个独立问题后再带 TCP 名称补充，检查归属。
6. 对比运行前后：无新 WorkItem、AgentTask、Entry、Memory 和审批消费，只有聊天、交互和请求回执变化。使用只读统计，不导出真实聊天。

### 路径 B：歧义、恢复与安全

1. 建两个等待材料的问题，直接贴一段无对象原文；应问 TCP 还是 UDP。用第二个浏览器标签保留旧问题。
2. 第一页回答，第二页用旧快照回答；应提示状态变化。刷新第二页后不应重复消费。
3. 在等待材料阶段刷新并重启服务，重新读取同库，检查恢复后能自然回答。保留服务启停和页面观察记录，数据库快照不单独算通过。
4. 撤销测试 Entry 后重试旧问题；应拒绝引用。需要模拟在途撤销的竞态由 fake model 阻塞点测试完成，不靠手速。
5. 输入“好/执行吧”，核对没有 Agent 任务启动。真实只读 CLI 的批准后执行另列实验，不在此脚本中开启。

## 6. 模型质量与 C4 报告

先冻结场景与期望再运行。对“那个实验”“握手那个”“TCP 是什么”“不是 TCP，是 UDP”“这段是新问题”做多种独立改写，加入否定、插话、多问题和未归档材料。准备至少 30 个正反场景作为首批质量集合；执行多少次由新的显式预算决定，未跑样本标未测，不能以 30 场景自动推定获得 30 次调用授权。

逐项报告分子与分母：

| 指标 | 分母 |
|---|---|
| 回复关系错绑、独立输入被误吞 | 所有实际判定的续接输入、独立输入分别统计 |
| 已知可回答仍追问、正确澄清 | 材料要求齐全样本、确有歧义样本分别统计 |
| 候选漏召回、选定来源错误 | 有已保存可用来源的请求、实际绑定次数分别统计 |
| 无证据误答、正确弃答 | 明确无可用证据的请求 |
| 改写新增事实/数字、遗漏用户约束 | 实际生成的改写答案；人工按原文逐条核对 |
| 点击次数、重新描述次数、模型实际请求数及延迟 | 每条完整用户路径；解释、回答、transport 重试均计入 |

冻结合同样本要求全部预期分支通过。质量试验发现的误绑/幻觉逐条归因；小样本零错误不表述成一般性保证。若解释模型增加调用却没有减少重复描述，保留确定性路径或缩小开放范围。新旧对照、失败修复和完整门禁完成后再决定 C4 默认切换，不提前将自然输入设为默认。

阶段验收报告应列提交 hash、样本版本、实际命令与通过/失败数、模型配置脱敏元数据（如适用）、浏览器观察证据及未测项。只提交合成 fixture 与脱敏总结，不提交数据库、截图中的真实私有内容、原始模型日志或密钥。
